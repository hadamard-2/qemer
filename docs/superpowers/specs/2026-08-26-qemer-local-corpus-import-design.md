# Qemer Local Corpus Import Design

## Goal

Keep Qemer a clean local corpus consumer while allowing a separately maintained `qemer-ingest` tool to hand it corpus artifacts produced on the same machine or served from any ordinary HTTPS location.

## Boundary

`qemer-ingest` is a separate repository. It owns source URLs, GitHub access, crawling, parsing, embedding, and every decision about how source material is obtained. Qemer does not accept a source repository or documentation URL, does not invoke `qemer-ingest`, and has no dependency on it.

The only integration surface is the existing manifest and `.tar.zst` artifact contract. Qemer imports an artifact, verifies it, builds its local LanceDB table, and searches it. It has no knowledge of how that artifact was created.

## Manifest sources and artifact resolution

`qemer available --manifest <source>` and `qemer install <library>@<version> --manifest <source>` accept either a local manifest path or an `https://` manifest URL. A manifest source is required; Qemer has no built-in catalog URL and does not contact GitHub Releases, R2, or another central host by default.

The existing `url` property in each manifest entry may be an absolute `https://` URL or a relative artifact path. Relative paths are resolved against the manifest source: next to a local manifest file for local imports, or relative to the manifest URL for remote imports. The resolved absolute location is what Qemer records in its local `corpus.json` metadata.

Each manifest may contain multiple versions of a library. A duplicate `(library, version)` pair is invalid, while `numpy@1.26.4` and `numpy@2.3.0` are distinct installable corpora. Qemer stores them separately and its picker shows both, letting the user select the version appropriate to the project at hand.

Qemer reads local artifacts directly and downloads HTTPS artifacts. It verifies the advertised byte count and SHA-256 before unpacking. It does not accept `file://`, arbitrary URL schemes, or a raw tarball without its manifest metadata.

## Command-line contract

The non-interactive commands are:

```text
qemer config
qemer available --manifest <path-or-https-url>
qemer install <library>@<version> --manifest <path-or-https-url>
qemer list
```

`qemer config` is an interactive terminal wizard. It creates or updates Qemer's normal configuration file without asking the user to locate it, prompting for the embedding/completion endpoints and models plus the completion context and answer-token limits. `qemer available`, `qemer list`, and `qemer install` need no configuration or running model server. Starting `qemer` without a subcommand remains the TUI and requires the configured model endpoints.

The Cargo binary is named `qemer`, and its `--version` output is generated by Clap from the package version.

## User-facing polish

The no-corpora TUI state shows the exact local-import command. A missing configuration error tells the user to run `qemer config`. The query input renders a visible insertion cursor while it is editable. Only an actual embedding connection failure tells the user to start an embedding `llama-server`; malformed or rejected embedding responses retain their specific error text.

## Non-goals

This work does not implement `qemer-ingest`, GitHub/source-repository ingestion, web crawling, a central corpus catalog, hosting, automatic model-runtime installation, a curl installer, cache eviction, or automatic corpus updates.
